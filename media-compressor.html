Media Compressor: choose the right settings

Media Compressor makes a new version of an image, audio file, or video using your browser. Choose a tab, open a source file, adjust the available settings, and inspect the result before saving it. The source file on your device stays available; keep it as your master copy so you can try a different setting later.

Smaller output is not guaranteed. An already efficient source can become larger when encoded again, especially if you choose a higher bitrate or a lossless image format. Compare the original and output sizes shown by the tool and keep the new file only if its size, appearance, and compatibility suit your purpose.

Images: begin with dimensions

Open the Image tab and select a photo, or drop one into the preview box. The maximum dimension setting limits the longest side while preserving the image’s proportions. Available choices include keeping the original dimensions, 1920 pixels, 1280 pixels, and 800 pixels. Reducing dimensions often has a larger effect than moving the quality slider a few points.

For example, if a 4000 × 3000 photograph only needs to appear in a small message, a maximum dimension of 1280 produces a much smaller pixel grid. Check whether fine details still matter to the recipient before choosing 800. For print, close inspection, or further editing, keep a larger version as well.

JPEG, WebP, or PNG?

JPEG is a practical starting point for ordinary photographs. WebP can be useful when the destination accepts it. PNG uses lossless image encoding and is often useful for sharp graphics or transparency, but it may be much larger for a photo. These are choices to compare, not a fixed ranking in which one format always wins.

The quality slider mainly affects lossy formats such as JPEG and WebP. PNG encoding does not use it in the same way. JPEG cannot retain a transparent background, so choose a format that supports transparency when it matters and inspect the export. A small output that changes the appearance is not automatically a successful result.

Start at the default quality, inspect the preview, and then lower it gradually if necessary. Look at fine text, faces, and areas with smooth color changes. Once the result is suitable, choose Download compressed image. A screenshot or phone camera format still has to be decodable by your browser before the tool can process it.

Audio: choose bitrate and allow time

Open Audio, select a file, and choose 64, 96, or 128 kbps. Try the lower setting for speech when size matters, then listen for words becoming rough or unclear. More complex audio may benefit from a higher setting. The right choice depends on the recording and destination, rather than the option label alone.

Press Start compressing and keep the page open. Audio is re-encoded in real time, so a five-minute recording takes roughly five minutes to process, plus setup and finishing. This is not a stalled upload: the work is happening on your device. Avoid letting the device sleep or navigating away while it records.

The output is WebM audio, generally using Opus where supported. It is not an MP3 converter. Use the result player to listen to the beginning and a later section, then download and test the file in the application where you plan to use it. Renaming a .webm file to .mp3 does not convert it.

Video: balance resolution and bitrate

Open Video and select the source. Choose a maximum height of 720p, 480p, or the original resolution. Then select a target bitrate of 800 kbps, 1.5 Mbps, or 2.5 Mbps. Lower resolution can be appropriate for a simple phone preview; a demonstration containing small text may need more detail.

Start compressing and keep the tab active. Video processing follows playback in real time and needs browser support for capture and recording. The output is WebM rather than a guaranteed MP4 replacement. Inspect movement, text, sound, and the end of the exported clip before relying on it. A still preview frame cannot reveal every problem in a video.

Why bitrate helps estimate size

For a rough audio estimate, multiply bitrate by duration and divide by eight to convert bits to bytes. A 60-second recording at 96 kilobits per second has about 720 kilobytes of encoded audio before container overhead, using decimal units. Actual recorder output can differ. Video estimates also need to account for audio and overhead.

Use estimates to choose a sensible starting setting, then measure the actual download. This tool targets quality, dimensions, or bitrate; it does not offer a guaranteed exact-byte-size export for every media type. For fixed photo dimensions and a JPEG maximum-size attempt, use the Exam Photo Resizer.

Troubleshooting and privacy

If recording is unavailable, try another current browser with the necessary media features. Support varies by device, input codec, and output format. If a large file makes the page slow, try a shorter or smaller source and close other demanding tabs. Do not assume every image, audio, or video extension is supported just because the file picker allows it.

Files are processed locally by the tool. The website can still request scripts, fonts, and advertising resources; local file processing does not mean the entire page has no network activity. Read the Privacy Policy for those services. For a decision process you can use on future files, read how to compare compression quality.

Working with a 3D model?

Use Model Workbench for GLB, glTF, FBX, OBJ, STL, and PLY assets. It can inspect geometry and textures separately; the media compressor handles ordinary images, audio, and video.
