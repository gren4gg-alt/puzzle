How to share a photo puzzle that still opens

A practical creator-to-recipient checklist for keeping a Photo Puzzle Exchange file playable.

Share the file, not a preview

A Photo Puzzle Exchange download has two jobs: showing the scrambled picture and carrying the information the game needs to recognize it. A chat preview can show the first part without preserving the second. This explains why a puzzle may look perfectly normal in a conversation but fail when the recipient tries to solve it.

The safest starting point is the original PNG made by Download & Share. Keep it in your downloads folder until you know the exchange worked. Do not replace it with a screenshot, an image copied from a browser preview, or a photo you saved from a messaging app after that app has processed it.

The creator’s checklist

  1. Choose the picture and grid in Create a Puzzle.
  2. Download the scrambled PNG and note its filename.
  3. Switch to Solve a Puzzle and load that same download to check that the board opens.
  4. Attach the tested download as a document or file in your chosen sharing service.
  5. Tell the recipient to save the attachment and load it in Solve mode.

You can test without finishing the puzzle: reaching the board confirms that the original file is recognized. It is still worth solving a small test puzzle once, so that you understand the recipient’s experience. Use a non-sensitive sample photo for that first test.

Choose a transfer route

For a messaging app, use its file or document attachment option where available. Sending through the photo picker can invite resizing, format conversion, or recompression. A file attachment is intended to preserve the actual file, but verify the received copy if the service’s behavior is unclear.

For email, attach the downloaded PNG as a file instead of pasting the image into the message body. If you use a storage link, direct the recipient to download the original rather than saving a rendered preview. Interface names vary, so the useful rule is to preserve the original attachment, not to follow one universal sequence of buttons.

A short message can prevent confusion: “Download this PNG attachment, open Photo Puzzle Exchange, choose Solve a Puzzle, and select the file. Please don’t screenshot or compress it.” The recipient does not need your source photo or a separate answer key.

The recipient’s checklist

Save the attachment to a folder you can find from your browser’s file picker. Open Photo Puzzle Exchange, select Solve a Puzzle, and choose the saved file. If the board loads, begin moving pieces from the tray. If it does not, keep the error message and ask for the original attachment again.

Be careful when there are several similar downloads. A completed image, a screenshot of the scrambled preview, and the actual puzzle may all resemble the same picture. Ask the sender for the filename of the tested puzzle. File extensions can help identify accidental conversions, but a .png name alone does not prove the contents survived unchanged.

Locate where the exchange failed

If the creator’s original opens and the recipient’s copy does not, test the transfer rather than recreating the image immediately. Compare file sizes and confirm that both people selected the intended attachment. Matching sizes are a useful clue, although they do not prove the bytes are identical.

If the original fails too, create a fresh small puzzle and test that download locally. If only a specific source image fails, report that pattern along with the browser and selected grid. If every small test fails, the issue may be with the tool or browser rather than the messaging service.

Do not run a damaged puzzle through another image editor hoping to restore it. Editing may preserve the visible picture while removing more of the hidden information. The reliable remedy is usually to return to the creator’s original working download and transfer that file again.

Share thoughtfully

Scrambling a picture is a game mechanic, not a security measure. Choose photos you have permission to share and avoid treating the puzzle as a way to hide sensitive information. The sharing service receives the attachment according to its own practices, even though creating and solving the puzzle happen locally in the browser.
