    How to use Model Workbench

    Model Workbench helps prepare a 3D asset for a web viewer, a game project, or another application. It imports the source into a working glTF representation, applies your settings, and builds the chosen output. Conversion can change materials or remove features the destination format cannot store. Keep your original project and work from a copy.

    1. Explore a sample or bring the complete model

    Choose Try sample model to create a textured, animated shape without selecting a personal file. For your own asset, use Add files, Add folder, or drag a ZIP into the page. A GLB often contains its resources in one file. A glTF may need a separate BIN and images; an OBJ may need an MTL and textures. Add related files together, keeping their folder structure in a ZIP when possible. Missing referenced files are reported rather than fetched from remote model URLs.

    2. Choose the destination before chasing size

    Set Output format first. Same as source retains a supported source format, but DAE and 3MF become GLB because this tool has no writer for those formats. Choose Game engine import when you want to avoid glTF compression extensions, then test the result in your actual importer. Web delivery uses Meshopt and WebP, which need compatible loading support. No profile guarantees acceptance by every application.

    3. Establish a baseline

    Automatic optimization is initially enabled. You can turn it off under Output to choose settings before processing. Select a queued model and press Optimize, or use Optimize all for a batch. Start without a target size and inspect the File size panel. A tiny source can become larger after conversion because the destination stores extra structure. Smaller download size and lower graphics-memory use are different goals.

    4. Reduce only what the asset can afford

    If textures dominate, lower their maximum dimensions gradually and check text, decals, and fine surface details. If geometry dominates, try triangle reduction and inspect the silhouette with Wireframe. Target size can search several combinations, but it may not reach your limit. Protect controls which kind of detail gives way first. Selected quality prevents further automatic reductions; it does not undo lossy options already selected. For a conservative starting point, choose Lossless cleanup only and leave the target blank.

    5. Compare, validate, and download

    Switch between Original and Optimized at the same camera angle. Original is the imported baseline, so compare against the source application too if conversion matters. Orbit by dragging, zoom with the wheel or pinch, and use Frame to find the asset. Check every animation in the selector when present. Read Validation and Log for warnings, then download the selected output. The validator checks the working GLB; it does not certify FBX, OBJ, STL, or USDZ exports.

    Reopen the downloaded file in its destination before replacing anything. A model can pass structural validation and still have an unwanted scale, missing texture, or altered appearance. Save the JSON report when comparing settings, and use Download all to collect completed batch results in a ZIP.

    Common problems and what to try

    • Missing textures: add the original model and its companion files together. Check filenames and paths rather than increasing texture quality.
    • Wrong size or orientation: check Source units and Up axis under Import. A unitless STL needs the correct unit assumption; avoid applying a second conversion to an already scaled asset.
    • A target is missed: inspect which bytes dominate. Raise the target or deliberately relax a setting. A larger output is possible and is not a reason to discard the original.
    • The engine does not load: check your connection and whether library requests are blocked. A current browser with WebGL support is needed for preview. Large models and KTX2 encoding can take substantial memory; try one model at a time.

    Models and generated outputs remain in the current tab until downloaded; reloading clears the queue. Compression settings are remembered in local browser storage. The page still requests libraries and fonts from third-party providers. See Privacy for details.
